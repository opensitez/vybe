# Parser execution checkpoint, 2026-10-04

The validated JavaScript grammar change is retained. This pass changes the parser and generator; both timing backends receive identical frozen grammar text and identical inputs. Default language backends remain pest.

Changes:

- Atomic token transitions execute in the dispatch loop instead of taking unnecessary scratch-stack round trips. Every logical task still charges the work budget.
- Capture checkpoints and semantic-builder checkpoints share one mark. Capture parsing uses `NoBuilder`; semantic builders do not collect capture nodes. Checkpoints shrink from 32 to 24 bytes and general tasks from 80 to 72 bytes.
- Atomic repetition stores its numeric bound and a bounded flag separately, shrinking atomic tasks from 48 to 40 bytes. Bounded empty repetition and unbounded non-progress behavior remain distinct.
- Generated literal choices index candidates by the first input byte when diagnostics are suppressed. Grammar order and original success/failure costs are preserved. Diagnostic-producing paths and tight work budgets use the original path.

The repeatable benchmark builds the frozen original core and current core in one release executable, together with black-box pest 2.8.6. The original core has a different crate name solely to keep the two Rust type universes separate. Each grammar is generated by its corresponding frozen/current generator. Timing includes capture construction and destruction, excludes grammar compilation and AST normalization, uses 10 warmups and 501 samples, and rotates original/current/pest order every round.

```sh
python3 crates/grameo/conformance_tests/tools/parser_engine_baseline.py --samples 501
```
